**网页（hot.reechi.work）的条款页和隐私页**：等 `industry/` 重组合并后另做，这里只记要点。

- 网页 `/terms` 和 `/privacy` 来自 `industry/pages/terms.md`、`privacy.md`，运营主体和联系方式换成锐奇，读者能看到的地方不出现上游框架的原名和 Logo。
- 网页条款可以参考 `user-agreement.md` 的第 3 到 5 节（AI 标识、版权、侵权投诉），但要保留网页模板里“使用本站的数据”和“接口与频率”两节：网页、RSS、公开 API、MCP 都是公开出口，小程序的协议不覆盖这些。
- 网页隐私页**不能照搬** `privacy-notice.md`：网页的反馈页会把反馈内容、选填的邮箱、页面地址和读者附上的截图存到服务器，网页没有“不收集个人信息”的前提。网页隐私页按网页模板的结构写。

## 2. 必须一字不差的段落

带【固定文案】标记的段落在下表的位置一字不差（包括全角括号、弯引号和“、；。”）。改一处，所有位置同步改，并重新请客户确认。发布到小程序或填表时，去掉标记行和 `<!-- -->` 注释，只留引用块里的文字。

| 固定文案 | 内容 | 出现的位置 |
|---|---|---|
| A 提醒例外 | 你点“提醒我明天的日报”时，为发这一次提醒，服务端保存微信提供的标识（openid）、目标日期、模板编号和创建时间；消息发出即删除，48 小时内没发出也删除；不做他用，不和任何其他数据关联，不进备份。不再点就不会再保存，48 小时内自动删除。 | ① 小程序隐私说明（`privacy-notice.md`）② 用户隐私保护指引的补充说明（`privacy-guidelines-form.md`）③ 无第三处：网页隐私页只讲网页，不含小程序的提醒；用户协议第 7 节只引用隐私说明，不复述 |
| B 访问日志 | 服务器依法保存访问日志（IP、时间、请求地址、浏览器标识），只用于网络安全和排障，到期删除。 | ① 小程序隐私说明 ② 用户隐私保护指引的补充说明。紧跟在 A 后面另起一句，不写成第二个例外 |
| C 锐奇 tab 声明 | 中文标题、摘要和日报由人工智能生成，仅作阅读索引，原文版权归各来源所有；不收集个人信息，唯一例外是点“提醒我明天的日报”时临时保存的微信标识；收藏只存在本机。 | 小程序“锐奇”tab 底部（`reechi-tab-copy.md`）。和规格 `docs/specs/reechi-hot-v1-spec.md`“合规文案”一节一致；原型 `reechi.html` 的写法不同，以这里为准 |

C 里的短句“不收集个人信息，唯一例外是点“提醒我明天的日报”时临时保存的微信标识”另外原样用在 `about-reechi-hot.md`（匿名一节）和 `review-notes.md`（审核备注第 4 点）。其他地方要提到这个例外，只用 A 的全文或这个短句，不另写第三种说法。

核对办法：在仓库根目录对 A、B、C 的全文各跑一次 `grep -rF '<全文>' docs/drafts/compliance/`，命中的文件和上表一致。

## 5. 还要定的事

1. **固定文案 A 的第三处**：已定，没有第三处。A 只在小程序隐私说明和用户隐私保护指引两处一字不差；锐奇 tab 用固定文案 C 里的一句话说例外；网页隐私页只讲网页，不含小程序的提醒。

# 用户隐私保护指引申报内容

> **v0.1 · 草稿，待客户确认** · 2026-10-17 起草
> 用在：微信公众平台小程序后台的“用户隐私保护指引”表单（一般在“设置 › 服务内容声明”下，路径和栏目名以提交时的页面为准）。开发起草，客户确认后提交。
> 带【固定文案】标记的段落和 `privacy-notice.md` 一字不差，填表时只粘贴引用块里的文字。

**提交前必做：** 按微信官方当时公布的隐私接口列表核对一次，确认下面点名的两项就是小程序实际用到的全部；同时在开发者工具里核对实际调用了哪些接口。不声明用不到的接口。

## 一、开发者处理的信息

只点名两项。除此之外，小程序不调用其他隐私接口，不获取手机号、头像、昵称、位置等信息。

### 1. 剪切板

| 栏目 | 填写内容 |
|---|---|
| 信息类型 | 剪切板 |
| 用途 | 只把来源链接写入剪切板，不读取剪切板内容。读者点“复制来源链接”时写入，方便到浏览器里打开原文。 |
| 对应接口 | `wx.setClipboardData`（只写入，不调用读取剪切板的接口） |
| 存储 | 不存储。链接只写进读者自己手机的剪切板。 |

### 2. 微信标识（openid）

| 栏目 | 填写内容 |
|---|---|
| 信息类型 | openid。[表单的信息类型列表里如果没有这一项，提交时确认填在哪里：自定义或“其他”一栏，或写进第五节补充说明] |
| 用途 | 只为发送读者主动订阅的日报提醒：读者在日报页点“提醒我明天的日报”并同意接收后，才获取并保存。 |
| 获取方式 | 读者同意订阅后，小程序调 `wx.login` 取临时登录凭证，服务端用它向微信换取 openid；同时返回的会话密钥丢弃，不获取 unionid。 |
| 保存什么、何时删除 | 按第五节【固定文案 A】。表单让选存储期限时，选能表达“最长 48 小时”的选项；没有对应选项的，写进补充说明。 |

## 二、信息的对外提供

不向第三方提供。openid 只用于调用微信的订阅消息接口，发读者订阅的那一条提醒。

## 三、第三方插件和 SDK

无。小程序没有接入第三方 SDK、插件或统计服务。

**【固定文案 A · 提醒例外】**

> 你点“提醒我明天的日报”时，为发这一次提醒，服务端保存微信提供的标识（openid）、目标日期、模板编号和创建时间；消息发出即删除，48 小时内没发出也删除；不做他用，不和任何其他数据关联，不进备份。不再点就不会再保存，48 小时内自动删除。

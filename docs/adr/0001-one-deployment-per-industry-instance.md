# 每个行业实例独立部署，不在一套部署里加行业维度

2026-10-17。要给锐奇的小程序加健康、运动两个板块，每个板块是一个行业实例。我们决定每个行业实例一整套部署（自己的数据库、worker、api），互不知道对方存在；小程序和聚合层只需要知道每个板块的 api 地址。没有选“单部署加 industry_id”：后端 20 个、前端 51 个文件静态引用 `@aihot/industry`，提示词目录写死；`reports` 按 (kind, key) 全库唯一，热榜、归组、日报的查询扫全表不按信源分，`articles.identity_key` 全库唯一，pg-boss 的定时任务是单例。加维度等于改十几张表和所有查询，事件会跨板块合并，而且上游仓库没走过这条路，以后同步上游会越来越难。代价是服务器资源和运维按板块数翻倍，我们接受。

## Consequences

- 想“加个 industry_id 省台机器”之前先读这份。
- 同一篇文章被两个板块的信源都抓到时，两边各存各的，各自评分，这是预期行为。
